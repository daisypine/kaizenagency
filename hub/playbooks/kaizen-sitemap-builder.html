Kaizen Sitemap Builder

Every Kaizen client gets ONE sitemap + project hub: a Google Sheet in the client's own Drive folder, named Sitemap - <Client> (Master). It is the single source of truth for every page on the site, what's live, what's planned by month, and every link the team needs. Never keep a second sitemap or a side status tab; merge into the master and trash the duplicate (it stays recoverable in Drive trash).

Reference hubs (copy their look exactly):

  • Falcon Roofing (original format): https://docs.google.com/spreadsheets/d/1lproWYjB34UBW6jjGZ0DN7Jqe_2aZO0kIgJAQZBxqDw/edit

Step 0 - Ask before running

Ask the team member (one message, max 6 questions):

  1. Client name, domain, and the client's Drive folder link

  2. Is there an existing sitemap or copy doc to merge?

  3. Any call transcripts, onboarding forms or emails to read (or which inbox to search)?

  4. Search Console / GA4 access? (domain property name)

  5. Main competitor, or a site the client says they like

  6. Services the client does NOT want promoted, and cities they actually serve If someone just says "build the sitemap for X", still ask these first. Don't start building on guesses.

Step 1 - Research (write findings to a scratch brief)

  • Crawl the live site: list every published page (WordPress REST /wp-json/wp/v2/pages?per_page=100&_fields=id,link,title and posts), nav items, footer links, forms, phone/address/license as shown. Flag 404s, placeholder text, duplicate pages.

  • Business facts: license #, address, phone, years in business, owner/contact, services they do and don't do, service area, brand spelling. Only facts the client stated or that are on official records.

  • Client words: search email + transcripts for project stories, client names they approved, target customers, seasonal patterns.

  • Socials: Instagram/Facebook for real jobs and photos (project page candidates).

  • Search Console: last 28 days (or since setup) clicks, impressions, avg position, top queries with impressions but low CTR. These decide which service/city pages come first.

  • Competitor: fetch <competitor>/sitemap.xml (or the site the client admires). List their sections and page types. Note what they lack (e.g. no page for the client's home city).

  • Reviews: where they live (Google, Yelp, Angi) and counts.

Step 2 - Plan the structure

  • Hubs with child URLs: /services/, /industries/ (if B2B), /projects/, /locations/, /blog/, plus About, Testimonials, FAQ, quote + bid forms, legal.

  • A page earns a row only if it has something real behind it (a real service, a real job, a real local project). Everything else goes to Backlog with a note like "only with a real job".

  • Phases: Phase 1 - Live (exists today), Phase 2 - <month>, Phase 3 - <month>, Phase 4 - <month>, Backlog. Put the money pages for the client's highest-impression queries first.

  • Pages the client doesn't want (services they don't offer) are not rows; log the decision in the Cleanup Log.

Step 3 - Build the hub sheet

  1. Create the sheet in the client's Drive folder (or reuse the existing one to keep its link).

  2. Copy these tabs from the Sunwest hub with copy_sheet_to_another_spreadsheet so the formatting, dropdowns and colors carry over: Overview, Sitemap, Cleanup Log, Competitor Gap, Project Inventory, Visual Sitemap, Templates, Content Calendar. Rename (drop "Copy of"), reorder, delete leftover tabs.

  3. Clear the copied values (keep formatting), then fill:

  • Sitemap (# | Phase | Section | Page Title | URL | Template | Status | Primary Keyword | Owner | Figma | Copy / Notes | Live / Edit | Notes). Row 2 holds the rule line. Use HYPERLINK() for Figma, copy doc and live links. Owner dropdown = Daisy, Basil, Team, Design, .

  • Overview: title row, client line, KEY LINKS (live site, WP admin, task board, gameplan page, brand guide, Figma, Drive folder, photos, print files, copy doc, emails, GBP, Search Console, GA4, booking link, socials, SOP) and live COUNTIF counts by Status and Phase pointing at the Sitemap tab. Tabs list + RULE row at the bottom.

  • Cleanup Log: open fixes first (Critical/High/Medium), then Done items. Status = Done, To Do, In Progress, Waiting on Daisy, Waiting on .

  • Competitor Gap: AREA | COMPETITOR | CLIENT TODAY | OUR MOVE | PRIORITY. Only what you actually saw; use "-" when unknown.

  • Project Inventory: real jobs only. Never private homeowner names or street addresses.

  • Visual Sitemap: tree by section with INDEX/MATCH formulas pulling Status and Phase from the Sitemap tab by page title.

  • Templates: the 6 templates (Home, Service, Industry/Materials, Project, Location, Content) with the page to clone and section order; PAGES column = COUNTIF on Sitemap.

  • Content Calendar: weekly GBP posts, review replies, blogs, monthly email, reports.

  1. Update dropdown lists (setDataValidation) and add conditional colors for any new Section/Channel values.

  2. Verify with get_values: counts add up, no #REF!/#N/A, Visual Sitemap statuses resolve.

Step 4 - Link it everywhere

  • Workspace board: add/refresh the 🔗LINKS 🔗 list with link cards (title + URL field): sitemap hub, Drive folder, photos, Figma, copy doc, gameplan page, brand guide, print designs, design files, email docs, WP admin.

  • Add the hub link to the client's gameplan page and SOP references.

Rules

  • Real facts only. No invented stats, certifications, quotes or projects.

  • One sitemap per client, in the client's Drive folder.

  • Don't name private homeowners; business clients only with permission.

  • Workspace board cards for the team stay unassigned unless Daisy says otherwise.

  • New pages stay WordPress drafts until Daisy approves.

  • Record any new lesson in the SOP (Client learnings log) and the relevant skill.
